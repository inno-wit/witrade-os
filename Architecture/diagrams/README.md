## What this is

The sixth sibling layer. Pages 00-16 each ship with a matching `.excalidraw` file, generated programmatically by a script in `../_scripts/`. That pattern covers the source ADD. It does not cover what the review added: 24 new or split containers, and nine formal state machines that exist nowhere in pages 00-16 because no page defines a state machine at all (`review/R07_State_Machines.md` §1).

This directory is that pattern, extended to the new material. Every file here is generated by a Python script under `_scripts/`, in the same style as the originals: `excalidraw_lib.py`'s `Diagram` class, boxes, arrows, labeled legends. `_scripts/sm_lib.py` adds state-machine-specific helpers (a `state_box` with semantic coloring, an `edge()`/`transition()` pair for routing labeled arrows between boxes) on top of the existing library rather than duplicating it — `../_scripts/excalidraw_lib.py` is imported, not copied, so the source generator scripts stay untouched.

## Reading these

Each diagram is a companion to its source text, not a replacement. The Mermaid in `review/R07_State_Machines.md` is the authoritative transition table with every guard, every dwell time, and every illegal-transition assertion; that detail is not duplicated here. Each `.excalidraw` file instead makes the **shape** of the machine legible at a glance — which states are terminal, which require a human gate, which are the "something is wrong" states — via consistent colour coding:

| Colour | Meaning |
|---|---|
| Green | Entry point into the machine |
| Blue | Ordinary operating state |
| Orange | Degraded, under evaluation, or (in the container diagram) newly added |
| Purple | Requires a human action or approval to leave |
| Red | Halted, failed, or an emergency condition |
| Gray, dashed | Terminal — the machine exits here |
| Cyan | Structural checkpoint, or (in the container diagram) split out of an existing container |

Every diagram carries a caption naming the one or two states that have no counterpart in the source ADD and why they had to exist — that is usually the single most load-bearing fact about the machine, and it is the fact most likely to get "cleaned up" by someone unfamiliar with why it is there.

## Regenerating

```
cd Architecture/diagrams/_scripts
python generate_16v2_container_model.py
python generate_sm1_platform_mode.py
python generate_sm2_deliberation_cycle.py
python generate_sm3_order_lifecycle.py
python generate_sm4_trade_position_lifecycle.py
python generate_sm5_model_lifecycle.py
python generate_sm6_kill_switch.py
python generate_sm7_data_source_breaker.py
python generate_sm8_data_quality_routing.py
python generate_sm9_deployment_release.py
```

Each script is independent and overwrites only its own output file. If a state machine's transition table changes in `R07_State_Machines.md`, or the container list changes in `generated/16_Container_Model_v2.md`, update the corresponding script and regenerate — the same discipline the source pages' own generator scripts follow.
